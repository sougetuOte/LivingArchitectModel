## §1 前提の裏取り（2026-07-27 / context7 / upstream-first §設計フェーズへの適用）

本設計の中核は「`.claude/rules/` から出せばロードされなくなる」に依存するため、先に確認した。

> `.claude/rules/` の**`paths:` frontmatter を持たない**ルールは**セッション開始時にロードされる**（`CLAUDE.md` と同様）。`paths:` を持つものは**一致するファイルを読んだときだけ**ロードされる。
> —— `code.claude.com/docs/en/claude-directory` / `docs/en/memory` / `docs/en/glossary`

**確定**: `.claude/rules/` の外に置いたファイルは auto-load されない。これが D2 の前提である。

**未検証として残すもの**: `.gitattributes` の `export-ignore` が GitHub の "Use this template" 経路に効くか（`git archive` 属性であるため ZIP / リリース tarball には効くが、template 生成と `git clone` はリポジトリの複製であり効かないと判断した / D1 §却下理由 β）。**この判断に依存する決定は本設計に無い**（β を採らないため）。

## §2 決定 D1: 境界の表現形式 = 配置そのもの（未決 1・6）

**「どこにあるか」が「誰のものか」を表す。マニフェストファイル・メタデータ列・分類表を作らない。**

| 場所 | 意味 |
|:--|:--|
| `.claude/rules/` | **製品**（配布する / 全ユーザーでロードされる） |
| `docs/private/` | **私物**（配布物としては無効 / ロードされない） |

### なぜ単一表現にするか

境界を「配置」と「マニフェスト」の 2 か所に持つと、**両者が drift する**。そして drift を検出するには検査機構が要り、検査機構は WC-10「配布マニフェストの第二統治面化」そのものである。

**配置が唯一の表現なら drift しようがない。** 検査すべき対象が存在しないため、NFR-3（検査機構を新設しない）が自動的に満たされる。

### 却下した実装手段

| 案 | 却下理由 |
|:--|:--|
| **α** `init-harness` を選別機構に拡張 | **新規機能の追加**であり FR-2「既存の配置・機構の再利用を優先」に反する。かつ init-harness は空の雛形を生成する足場組みスキルで、選別すべき対象を最初から持たない（rationale §2.3） |
| **β** `.gitattributes` の `export-ignore` | **主要 2 経路に効かない**。`export-ignore` は `git archive` の属性であり、ZIP ダウンロードとリリース tarball には効くが、**"Use this template"（リポジトリ複製）と `git clone` はそのまま全量を運ぶ**。かつ**配置とは別の第二の記録面**になり WC-10 に触れる |
| **δ** 配布を諦めて明示する | 決定 2「配布可能性を維持する」と衝突する |

## §3 決定 D2: 除外資産の置き場（未決 3）

**`docs/private/` へ移す。git の追跡は継続する。**

### 検討した 4 案と選定理由

| 案 | 所有者環境で有効 | 配布物から消える | 版管理 | 判定 |
|:--|:-:|:-:|:-:|:--|
| **`.claude/rules/` に残し `.gitignore`** | ✅ | ✅ | **✗** | **却下** —— 18KB の統治文書が追跡外になる。`rm` 一発で消え履歴も残らない。PM 級保護（`_PM_PATH_PATTERNS`）も外れる |
| **`docs/private/` へ移す（採用）** | **✗**（下記で補う） | △（ファイルは残るが**無効**） | ✅ | **採用** |
| `~/claude-global-assets/` へ出す | ✅ | ✅ | ✅ | **保留** —— ADR-0010 が確立した personal 層の版管理先だが、**ユーザースコープの rules ディレクトリの有無が未検証**。D-1 では採らない |
| 別リポジトリへ分離 | ✅ | ✅ | ✅ | **却下** —— リポジトリ分割は死んだ案 #5（FR-3 が MUST NOT） |

### 「配布物から完全には消えない」ことを受け入れる理由

`docs/private/` のファイルは、3 つの配布経路すべてで**コピーされる**（リポジトリ複製のため）。しかし:

- **ロードされない**（§1 の裏取り）。新規ユーザーの Claude が毎セッション 18KB の他人の規律を読むことがなくなる —— **これが実害の本体である**
- ディレクトリ名が意味を持つため、新規ユーザーは**1 コマンドで削除できる**
- 「消えない」ことの残余は認知的なノイズであり、**機能的な害ではない**

**したがって D-1 が解くのは「配布物に含まれるか」ではなく「配布先で有効になるか」である。** requirements §1 の「私物まで渡してしまっている」に対する回答としては部分的だが、**実害のある部分は全部消える**。この限定を明示する。

### 所有者環境での有効性（FR-6）

`docs/private/` はロードされないため、**所有者も自動ロードを失う**。これを次で補う。

- **原則**: 移す対象は「**所有者にとっても常駐が不要**なもの」に限る。常駐が必要なら移さず、後述の**分割**で私的部分だけを抜く
- **分割後に残る私的部分**（パス・予算数値・外部リポジトリ名）は**参照される値**であって**常駐すべき規律**ではない。必要時に読めばよい
- FR-6 の確認は「pytest 全系統が緑」で行う（成功基準 4）

## §4 決定 D3: 判定の出力を 3 値にする（未決 2・4）

### 出力

| 出力 | 意味 | 操作 |
|:--|:--|:--|
| **P（製品）** | 配布物。他人の環境で意味を持つ | `.claude/rules/` に据え置き |
| **X（私物）** | 他人の環境で意味を持たない | `docs/private/` へ移す |
| **S（要分割）** | 製品部分と私物部分が同一ファイルに混在 | 私的部分を抜き、残りを P として据え置く |

**S を認める理由**: R1 の主要ファイルは混在が支配的だと予想される。例えば `fable-l3-protocol.md` は、外部リポジトリのパス（私物）と、自己監査 14 項目・体験シミュ・F0-F4（**LAM の製品価値の中核**）が同居している。2 値判定を強制すると「製品の中核を私物として捨てる」か「私物を配り続ける」の二択になり、どちらも誤りである。

### S は手 4 の先取りではない（requirements §5 未決 2 の MUST への回答）

| | 手 4（経路 1） | D-1 の S |
|:--|:--|:--|
| 軸 | 「この記述は**要るか**」（矛盾統制） | 「この記述は**誰のものか**」（配布列） |
| 対象 | superseded な推論の注記 | 個人の環境・予算・外部リポジトリへの参照 |
| 読者 | `/update-model` ステップ 5 と HGA ブリーフ | **配布先の他人** |
| 判定者 | L1（矛盾の検出） | **ユーザー本人**（NFR-2） |

**軸が直交しているため、S を実行しても手 4 は未着手のまま残る。** 逆に、S で抜いた私的部分が「実は矛盾の解消にもなっていた」場合でも、それは副産物であって D-1 の目的ではない（**目的化しない** —— 目的化すると (a) の脱法になる）。

### 手順（未決 4）

1. **証拠収集**（L1 が実行 / NFR-2 の「結論を出さない情報提示」の範囲）
   - 15 ファイルそれぞれについて、**配布列に該当する記述を機械的に抽出**して並べる
   - 抽出対象: 絶対パス（`D:/work7` 等）/ 外部リポジトリ名（`Fable-Alembic` / `etc-to-alembic`）/ 個人の予算・単価の数値 / 個人名・アカウント名 / 他プロジェクト名
   - 出力は「ファイル名 / 該当箇所 / 該当行の引用」の表のみ。**P/X/S の下書きを付けない**
2. **判定**（ユーザーが実行）
   - 証拠表を見て 15 件に P / X / S を付ける
   - 判定は 1 回のセッションで完了させる（**中断すると基準が揺れる** / handoff §6 経路 2 の「1 条項 30 秒」に相当する速度で回す）
3. **反映**（L1 が実行）
   - X → `docs/private/` へ移動
   - S → 私的部分を抜き、抜いた内容を `docs/private/` の 1 ファイルに集約
   - P → 変更なし
4. **波及処理**（D4）
5. **検証**: pytest 全系統 + §A カウント（成功基準 4・5）

## §5 決定 D4: 判定の波及先（未決 5 + 設計上の発見）

### 発見: R1 ファイルの判定は、それを参照する機構に波及する

FR-4 は判定対象を R1 の 15 ファイルに限定したが、**判定の結果は R1 の外に波及する**。

| 波及先 | 内容 |
|:--|:--|
| `.claude/hooks/pre-tool-use.py` | `_OUTBOUND_WRITE_BAN_ROOTS` は `fable-l3-protocol.md` §2 を SSOT とする |
| `.claude/tests/hooks/test_outbound_write_ban.py` | `test_banned_root_matches_rule_document` が条文の**存在と内容**に依存する |
| `.claude/tests/rules/test_clause_gate_ledger.py` | R1 集合を実測して台帳 §A と突合する（**ファイルが減れば §A も動く**） |
| `docs/artifacts/clause-gate-ledger.md` §A | 同上 |

**したがって「X または S に判定されたファイルがある場合、上記 4 か所を同一の波で更新する」ことを設計上の義務とする。** 更新漏れは §A 不一致として `test_clause_gate_ledger.py` が検出する（**出口の不動点が既に存在する**ため新規機構は不要）。

### 成功基準 3 への回答（未決 5）: **「置かない」を採る**

> 成功基準 3: `_OUTBOUND_WRITE_BAN_ROOTS` の**無条件**実在検査を置けるようになる、**または**「置かない」判断の根拠が記録されている

**置かない。** 根拠は以下のとおり。

1. `fable-l3-protocol.md` が X または S に判定されても、**hook 本体（`pre-tool-use.py`）は D-1 のスコープ外**である（FR-4）。ハードコードされた定数はそのまま残る
2. かつ **D-1 は同型の問題を 1 つ増やす** —— 条文が `docs/private/` へ移れば、`test_banned_root_matches_rule_document` も配布先で落ちるようになるため、**同じ所有者ゲートが必要になる**
3. 無条件検査が置ける条件は「hook・テスト・条文がすべて配布物から外れる」ことであり、それは**hooks を対象に含む後続 Milestone の仕事**である

**したがって D-1 完了時点でも所有者ゲートは残る。** これは失敗ではなく、スコープを R1 に絞ったことの当然の帰結である（requirements §2 の「決めない」に skills / agents / hooks が入っている）。

## §6 決定 D5: 将来 R1 に追加されるファイルの責任（未決 7）

**誕生ゲート（`.claude/skills/clause-gate/`）の既存 Step に、配布列の 1 問を足す。**

```
（既存）Step 1 機構テスト → R3 か
（既存）Step 2 繋留判定  → R2 か
（既存）Step 3 …          → R1 / R4 / R5
（追加）R1 に決まった場合のみ:
        「この条項は私の環境・予算・他プロジェクト・個人名を参照するか」
          → Yes なら docs/private/ へ、No なら .claude/rules/ へ
```

### FR-5 に違反しない理由

FR-5 が禁じるのは「**定期再判定**の手続を条文化すること」である。本決定は**新規条項が生まれる瞬間の 1 回の判定**であり、既存条項の再判定ではない。**時計を持たない**（定期実行の契機が存在しない）ため、WC-11「主権審査の制度化」の機序に乗らない。

### 新規機構を作らない理由

誕生ゲートは既に稼働しており（`test_clause_gate_ledger.py` が出口の不動点）、**追加するのは判定順序への 1 問のみ**。新しいファイル・スキル・テストを作らない。

## §8 代替案（採らなかった設計）

| 案 | 却下理由 |
|:--|:--|
| **マニフェストファイルを 1 枚作る** | 配置との drift が生じ、drift 検出のための検査機構が要る = WC-10 直撃。**配置を唯一の表現にすれば問題ごと消える** |
| **frontmatter に `distribution: private` を足す** | 全条項がチャネル書類仕事を負う = **WC-16「配送台帳の第二憲法化」**そのもの |
| **判定を 2 値（配布 / 非配布）に強制** | 混在ファイルで「製品の中核を捨てる」か「私物を配る」の二択になる（§4） |
| **`.gitignore` で私的規律を追跡外にする** | 所有者環境では最も綺麗だが、**18KB の統治文書が版管理から外れる**。PM 級保護も外れる（§3） |
| **判定を L1 が下書きしてユーザーが承認** | NFR-2 違反。M-1 の自己申告問題の再生産（HGA #20 D-2） |
