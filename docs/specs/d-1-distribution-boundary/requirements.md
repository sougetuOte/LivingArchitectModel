## §0 なぜこの Milestone を立ててよいのか（合法性の根拠）

M-1 の出口宣言 (a) は「**consolidation 系 Milestone のジャンルをここで閉じる**」と定めた。本 Milestone はこれに抵触**しない**。

| | (a) が閉じたもの | 本 Milestone |
|:--|:--|:--|
| ジャンル | **consolidation 系** —— 規範文書が肥大化していないかを問う棚卸し | **製品定義の変更** —— 何を配布物とするかを決める |
| 問い | 「この条項は要るか」 | 「この条項は**誰のものか**」 |
| 出力 | 条項の削除・移動 | **パッケージング境界（マニフェスト）** |

この区別は L1 が本 Milestone のために発明したものではない。`CHANGELOG.md` の「**次 Milestone の性格の明示**」が、（撤回された）移住案について既に同じ区別を記録している:

> 本作業は出口宣言 (a) が閉じた「consolidation 系」ではなく、**製品定義の変更**である。ジャンルが異なることを記録しておく。

移住案そのものは撤回された（死んだ案 #5）が、**ジャンル判定は撤回されていない**。本 Milestone は同じ判定を継承する。

### スコープに入れないもの（重要）

**手 4（経路 1 = R1 内の埋込統治記録の剥離）を D-1 に含めない。** 手 4 は常駐面の質量を問う作業であり consolidation 寄りである。製品定義 Milestone に同梱すると **(a) の脱法**になる。手 4 は引き続き Milestone 外の「手」として扱う。

## §1 背景

### 1.1 発端となった具体的な詰まり

`.claude/hooks/pre-tool-use.py` の不可逆ガードに、開発者個人の環境の絶対パスが埋まっている。

```python
_OUTBOUND_WRITE_BAN_ROOTS = (Path("D:/work7/Fable-Alembic"),)
_OUTBOUND_WRITE_ALLOW_ROOTS = (Path("D:/work7/etc-to-alembic/handoff"),)
```

MAGI はこれを「パスの修正」として直すことを**否決**した（兄弟導出 / 設定ファイル化 / 条文パースはいずれも死因つきで記録済）。沈黙の検出は所有者ゲートつきテストで解決済み（commit `6689bd0`）。**残ったのは、この定数が参照する `.claude/rules/fable-l3-protocol.md` が R1 = 配布物に含まれている**という事実である。

### 1.2 未決であることが塞いでいるもの

| 塞がっているもの | 理由 |
|:---|:---|
| ban root の**無条件**実在検査 | 配布先の pytest が落ちるため置けない（現在は所有者ゲートで回避） |
| `hga-summoning.md` の扱い | 個人の予算枠・モデル選択・外部リポジトリを参照する（R1 最大 20,003 バイト / 9 指令） |
| `fable-l3-protocol.md` の扱い | 外部リポジトリ `D:\work7\Fable-Alembic` との連携規律（R1 18,588 バイト / 19 指令 = 指令密度 1 位） |
| 「配布可能な製品として維持する」（決定 2）の実効性 | 何が配布物かが未定義のまま「維持する」と宣言している状態 |

### 1.3 self-hosting との関係（制約）

HGA #22 が「**self-hosting は原則ではなく LAM 唯一の QA 機構**」と裁定した。したがって:

- **開発環境と配布物をリポジトリ境界で分けてはならない**（移住 = 死んだ案 #5 / ユーザー撤回済）
- 境界は**パッケージング境界**（マニフェスト）として実装する
- 2026-07-27 の WSL2 検討で ① 現状維持が確定した理由も同根（**WC-12「dogfooding の名目化」のプラットフォーム版**）

## §2 目的

**LAM のどの資産が配布物で、どれが開発者個人の統治記録かを判定できる状態にする。**

判定基準は既存の枠組みを流用する。`docs/artifacts/lam-reconstruction-handoff-2026-07-27.md` §6「経路 2 の 2 列」の**配布列**:

> 「この条項は私の環境・予算・他プロジェクト・個人名を参照するか」（ほぼ機械判定）

**新しい判定軸を発明しない。**

## §3 要件（RFC 2119）

### 機能要件

| ID | 要件 |
|:--|:--|
| **FR-1** | 配布物と非配布物を判定する基準を明文化 **MUST**。基準は §2 の配布列を流用し、新規軸を追加 **MUST NOT** |
| **FR-2** | 判定を実装する先は `.claude/skills/init-harness/` の**既存選別機構** **MUST**。新規の選別機構を作ること **MUST NOT** |
| **FR-3** | 判定結果は**パッケージング境界（マニフェスト）**として表現 **MUST**。リポジトリを分割すること **MUST NOT**（self-hosting 維持 / §1.3） |
| **FR-4** | 全 R1 ファイル（15 件）と `.claude/skills/` `.claude/agents/` `.claude/hooks/` を判定対象に含める **MUST** |
| **FR-5** | 判定結果は**単発の記録**として残す **MUST**。定期再判定の手続を条文化すること **MUST NOT**（WC-11 防御 / §5） |
| **FR-6** | 配布物から除外される資産について、**除外後も self-hosting が成立すること**を確認 **MUST**（開発環境では引き続き全資産が有効であること） |

### 非機能要件

| ID | 要件 |
|:--|:--|
| **NFR-1** | 本 Milestone は §A 常駐指令カウントを増やさない **SHOULD**（増やす場合は誕生ゲートを通す **MUST**） |
| **NFR-2** | 判定作業に L1 / L2 / L3 の事前採点を用いること **MUST NOT**（M-1 の自己申告問題の再生産 / HGA #20 D-2）。判定者はユーザー本人 **MUST** |
| **NFR-3** | 成果物に「何が配布物か」の**検査機構**を新設すること **SHOULD NOT**（WC-10 防御 / §5） |

## §4 成功基準

1. **全 R1 ファイル 15 件について配布/非配布が決まっている**（未判定ゼロ）
2. **`init-harness` が判定結果に従って選別できる**（実行可能であること / 手順書だけでないこと）
3. **`_OUTBOUND_WRITE_BAN_ROOTS` の無条件実在検査を置けるようになる**、または「置かない」判断の根拠が記録されている（§1.2 の詰まりが解消したことの観測可能な指標）
4. **self-hosting が壊れていない**（開発環境で pytest 全系統が緑 / 現在 1182 passed + 14 skipped）
5. **§A 指令カウントが 80 を超えていない**

## §6 検討した代替案

| 案 | 却下理由 |
|:--|:--|
| **リポジトリ分割**（移住） | self-hosting 維持下では開発環境 = 製品リポジトリであり分割対象が存在しない。**死んだ案 #5**（ユーザー撤回 + HGA #22） |
| **パスだけ直す**（兄弟導出 / 設定ファイル化） | 沈黙の条件をずらすだけで消さない。**MAGI で否決済**（`2026-07-27-magi-outbound-ban-path.md` §死んだ案） |
| **何もしない** | §1.2 の 4 つの詰まりが残り続ける。特に決定 2「配布可能性を維持する」が未定義のまま宣言だけ立っている状態が続く |
| **新しい判定軸を作る** | 転落条件 ② の脱法（4 軸に存在しない軸で既収載 80 件を再ソート）。**死んだ案 #7** |
