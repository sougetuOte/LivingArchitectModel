## day-1 実測メモ (召喚 #2 / branch モード / 2026-07-02)

- **branch モード成立確認**: Fable が Agent ツールで Sonnet subagent 3 体を起動できた (技術的可否 = 可)。
- **コスト暴発を実証**: 通常召喚 #1 ~85k に対し branch #2 は ~646k tok (約 7.6 倍)。規律「branch モードは稀・バウンド付き」の裏付け。孫の 1 体 (sweep) が監視/待機に終始し実質重複 = branch は制御が緩いと孫が暴走する。
- **オーケストレーション特性**: Fable はターンを中断して中間報告を返し、孫完了は L1 に通知された (Fable に自動再開なし)。branch の統合には L1 の再介入が必要 = 通常召喚より往復構造が重い。
- **運用結論**: branch モードは今回の実測で「高コスト・制御難」が確認できたため、既定は通常召喚 (索引 push で自力調査) とし、branch は真に必要な適応探索に限りバウンド (孫数・深さ) を明示して使う。本件の設計統合は L1 が引き取る (これ以上の再帰を避ける)。

### 主 crux への裁定 = **R1 を「純粋なコスト」として価格づけたことが最深の誤り**

> LAM の間違いは「数えたものを管理し、数えられないものを放置した」ことではない。**逆である。数えたもの（指令カウント）には upstream 上の物理が存在せず、数えなかったもの（質量・矛盾・配送チャネル）にこそ物理があった。**
>
> しかし最も深い誤りはもう一段下にある —— **R1 は基質が提供する唯一の compaction 耐性・subagent 全継承の散文チャネル、すなわち最上級の配送チャネルである。コストであると同時にプレミアム便である。カウント通貨は「R1 から退去させること」を常に利得として計上するため、最良のチャネルからの退避を系統的に過大報酬してきた。**

**「指示が効かない」は 1 つの現象ではなく、独立した 3 つの物理に分解される**:

| 物理 | 内容 |
|:---|:---|
| **配送の失敗**（届いていない） | `paths:` 条項の compaction 死 / skill 本文の 5k・25k 打ち切り / イベント繋留条項に配送機構がないこと |

| **恣意的選択**（届いて読まれたが矛盾の相手に負けた） | 公式明言「矛盾する 2 規則はどちらかが恣意的に選ばれる」。**Hierarchy of Truth はこの調停者を自称するが、それ自体が prompt であり同じ抽選箱の中にいる** |

**置換すべき設計目標**: 分類の第一軸を「テキストがどこに保管されるか」（R1-R5 = **保管所**の分類）から「**その指示が、統治対象の行為の瞬間に、どのチャネルで到着するか**」（**配送**の分類）へ移す。

**配送チャネルの階層（基質側で既に階層化されている / 強い順）**:

### 副問 2: R2 降格は罠だったのか = **罠ではないが「減量の成功」という記帳は誤りで、正しくは「リスクの交換」**

R1 退去は**注意希釈リスクを配送死リスクと交換する取引**であり、カウント通貨はこの取引を**無料の利得に見せた**。

- **`planning-quality-guideline.md`**: アンカー（`docs/specs/**`）の読み込みが、条項を必要とする作業そのものの中で高頻度に再発する。compaction で死んでも次の spec read で蘇生する = **自己再武装するアンカー**

### 副問 3: enforcement / judgment の分割線 = **判定規則は新設不要**

**clause-gate Step 1 の 3 条件（入力にスキーマ契約 / exit-code 級機械判定 / 意味解釈不要）が、upstream の「毎回成立しなければならないなら hook にせよ」の LAM 語訳としてそのまま使える。** 問題は規則の欠如ではなく**適用範囲** —— Step 1 は誕生ゲート（フロー）専用で、既収載 80（ストック）には一度も適用されていない。

### 副問 4: 矛盾の機構化 = **検出の完全機構化は不可能。機構化できるのは「兵糧攻め」**

## §25 詳細（2026-08-15 / 通常モード / **外部プロダクトの設計思想の輸入可否**）

**L1 の暫定判断は却下された。** L1 は「Continual Harness の **CRUD 対称性という『形』だけ輸入し、自己書換の『権限』は輸入しない**」を暫定判断として提示し、追認ではなく独立検証を指示した。

**① 争点の再定義（3 点）**

- **争点 A**: H = (ρ, G, K, M) は「4 面の分類学」と「4 面を貫く同一ライフサイクル」の 2 層でできている。**分類学は LAM が既に持つ**（R1〜R5 の配送先分類とほぼ同型）ため輸入の新規性がない。持っていないのは後者 = **4 面のうち 3 面（skills / agents / memory）にライフサイクル規律（証拠閾値 → 起票 → 承認 → 退役）が存在しない**こと。これは WC-13「境界固着の側圧」が名指しした「計器のない地層」と一致する
- **争点 B**: 「FR-9 と self-modifiable harness state は正面衝突」という L1 の前提は**過大**。prime-agent も**不変のベース system prompt は書き換えない**ため、両者は「憲法コアは不可侵・周縁は可変」という同じ位相を持つ。かつ LAM の周縁は既に自己書換可能（memory = PG 級自動記録 / agent-memory = 公式機構 / skills・agents = SE 級）。**LAM は self-modifiable harness state を持っていないのではなく、持っているのに統治していない**
- **争点 C**: compaction の穴の本質は「保存」ではなく「**再想起のトリガ所有権**」。両者とも状態は耐久基質に残る。差は、条件ロードの再想起が**イベント繋留（失火は不可視）**なのに対し、prime-agent では**モデル自身の関数呼び出し（失火が trajectory 上で可視）**である点だけ

**② L1 の暫定判断への異議 4 点**（うち 2 点は L1 の利害相反の指摘）

1. 「FR-9 と正面衝突」の誇張と「/refine ≈ 既存パイプライン」の等価読みは、**両方の歪みが同じ結論（形だけ輸入 = 実質輸入なし）を支える方向を向いている**
2. 等価読みは **ρ 面限定でのみ真**。K/G/M の無統治は L1 自身の WC-13 認定と接続しており「新規性ほぼ無し」はこの接続を切断している
3. L1 の仮説「輸入すべきは『育て方』ではなく『育ったものを安全に捨てる形』」は、**ドナー不在で成立しない** —— prime-agent に実証された「捨てる形」が存在しない
4. 「CRUD 対称性の形だけ輸入」は**却下**（既所有 + WC-16 直撃 + **等コスト対称は削減に無力**）

> **④-3 の一次資料による裏づけ（L1 が往復で解決 / 2026-08-15）**: 公式ブログ上、`delete_X(...)` は CRUD 面に**実在する**が、**eviction / pruning / decay / garbage-collection / 予算のいずれについても記述が存在しない**（受入基準・成功指標・検証ゲートの明示もない）。**D は API として存在し、力学としては存在しない** —— LAM の 90 日棚卸しが一度も発火していないのと同型。

### output 記録破損ケース (#4 の分析)

HGA #4 は召喚 log に「tool_uses 0」と記録され、`agent-*.jsonl` の usage 記録も
2 メッセージ × `output_tokens=2` (計 4 tok) と極小。しかし応答本文の text は
**6,748 chars 存在** し、内容は完全 (分岐点 1〜3 + 盲点セクション全て完成)。

**根本原因**: tool_use が 1 回もない一発応答召喚では、jsonl に `message_start` と
中間 `message_delta` の 2 イベントしか記録されず、最終 `message_end` の usage 合算が欠落。
両イベントとも `stop_reason=None` になる。

**再現条件**: `tool_uses=0` かつ text-only 応答の召喚のみ。tool_use が 1 回でも
挟まれば各 API 呼び出しごとに正常な usage が記録される (#1/#3 で verify)。

**envelope 監視への影響**: tool_uses=0 召喚は 1 件あたり output ~7k tok (= $0.3-0.5) が
過小記録される。今後の集計では手動加算するか、実測は text char 数 × 0.8-1.5 で推定する。
