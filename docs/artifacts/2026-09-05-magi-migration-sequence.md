## Atom A1: E2E の検証対象と合格条件

**[MELCHIOR]**: 5 点で足りる。install が通る / `/lam-harness:init` が完走する / skill が名前空間で起動する /
agent が解決する / hook が発火してガードが効く。これが通れば「配って問題ない」と言ってよい。
`lam-p1` は既に init まで通っているので、差分だけ足せば速い。

**[BALTHASAR]**: 3 点で反対する。

1. **「init が完走した」と「敷いたものが機能する」は別物である**。scripts 12 件を敷いても、
   `bash .claude/scripts/py_invoke.sh -m pytest` が利用者環境で通るかは別に確かめねばならない。
   init の Step 5 は**件数一致**しか見ていない
2. **`lam-p1` は再利用してはならない**。scripts 追加前の init 結果が残っており、
   「敷かれたのか、前から在ったのか」が区別できない。**汚染されたサンドボックスは陰性対照にならない**
3. **fresh clone の赤 3 件が未解消**のまま E2E を通しても、「LAM 開発機だから通った」可能性を排除できない。
   E2E は**別ディレクトリ・別 git 履歴・LAM の `.claude/` が親に無い**場所で行う必要がある

**[CASPAR]**: 結論: **合格条件を 6 項に定め、サンドボックスは新規に切る**。

| # | 合格条件 | 検証方法（実コマンド / 観測） |
|:-:|:--|:--|
| **E1** | marketplace add → `install --scope project` が通り、`.claude/settings.json` に `enabledPlugins` が入る | `claude plugin list --json` に `lam-harness` が出る |
| **E2** | `/lam-harness:init` が完走し、managed 36 + starter 8 が敷かれる | `.claude/rules` 14 / `docs/internal` 10 / `.claude/scripts` 12 の件数一致 |
| **E3** | 敷いた scripts が**実際に動く** | `bash .claude/scripts/py_invoke.sh -c 'import sys; print(sys.version)'` が 0 で返る |
| **E4** | skill が名前空間で起動する | `/lam-harness:building` 等が解決し、本文がロードされる |
| **E5** | agent が解決する（**P1(2)(3) をここに吸収**） | bare `subagent_type=gabriel` の解決可否 / description 衝突の有無 |
| **E6** | **hook が発火してガードが効く** | PM 級パス（`.claude/rules/*.md`）への Write が承認ゲートに掛かる |

**採用しなかった選択肢とその理由**:
- **`lam-p1` を再利用する** → 汚染により陰性対照が成立しない（BALTHASAR 2）
- **E6 を後回しにして E1-E5 で合格とする** → **ガードが動かない harness は LAM ではない**。
  配布物の価値の中核が未検証のまま「問題ない」と言うことになる
- **E3 を件数一致で代用する** → init Step 5 が既にやっており、二重で同じものを測るだけ

## Atom A2: hooks.json の投入時期と、LAM 本体の防御

**[MELCHIOR]**: 今すぐ置ける。A1 の E6 が hooks 抜きでは測れない以上、**hooks.json は E2E の前提条件**である。
そして install スコープを `project` に限れば捨てプロジェクトの `.claude/settings.json` にしか書かれず、
LAM には及ばない。**LAM は現在未 install であり、未 install なら plugin hooks は走らない**。

**[BALTHASAR]**: 危険は 2 つあり、どちらも**人間の操作ミス 1 回で発火する**。

1. **`--scope` の既定が `user` である**。`claude plugin install lam-harness@sougetuote-lam` と
   打つと user スコープに入り、**全プロジェクト = LAM 自身にも及ぶ**。その瞬間 project hooks 7 件と
   plugin hooks 7 件が**両方走り**、`tdd-patterns.log` に復元不能な二重追記が起きる
2. **`--plugin-dir` は install 不要で直読みする**。LAM リポジトリで 1 回使えば同じ結末になる。
   SESSION_STATE 注意 (1) が最重要として掲げているのはこれである

さらに ADR-0010 **I-2** が「enable はプロジェクトスコープでのみ」と既に定めている。
**user スコープ install は I-2 違反であり、規範上も禁じられている**。

**[CASPAR]**: 結論: **hooks.json は E2E の直前に置く。ただし防御を 3 枚同時に立てる**。

| 防御 | 内容 | 性質 |
|:--|:--|:--|
| **D-a** | install は必ず **`--scope project`** を明示する。手順書に素の `install` を書かない | 規範（I-2 の運用形） |
| **D-b** | **LAM 自身が `lam-harness` を有効化していないこと**を検査するテスト | 機構（**新設せず既存テストに追加**） |
| **D-c** | E2E は**捨てプロジェクトでのみ**行う。LAM リポジトリで `--plugin-dir` を使わない | 規範（SESSION_STATE 注意 (1) の再掲） |

**D-b の実体**: LAM の `.claude/settings.json` / `settings.local.json` に
`enabledPlugins` の `lam-harness` エントリが**無い**ことを assert する。
`~/.claude/plugins/installed_plugins.json`（上流の私有状態）は読まない
（HGA #30 の決定「上流の私有状態を自前パースしない」に従う。**自分側の設定ファイルを読むだけ**）。

**採用しなかった選択肢とその理由**:
- **hooks.json を self-hosting フェーズまで置かない** → E6 が測れず、A1 の合格条件を満たせない。
  「配布して問題ない」の核心を未検証のまま第 2 段へ送ることになる
- **R3 機構を新設して防御する** → 台帳 §A は 56/80。**テスト 1 本で足りるものに通貨を払わない**
- **`strictPluginOnlyCustomization: ["hooks"]` で LAM 側の project hooks を止める** →
  `settings.json` は **AI 編集不可**（ユーザー手作業）であり、かつ
  `hooks-local/outbound-write-ban.py` も巻き添えで止まる。**P4 の選択肢としては保持するが、A2 では採らない**

## Atom A3: 検出器 3 種の位置

**[MELCHIOR]**: 前セッションは「検出器は P2 撤去より前」と決めた。しかし**ゴールが C に変わった**。
検出器 3 種はいずれも「**LAM 自身が install した後**」に初めて効く。E2E 先行なら LAM は install しない。
よって **A4-P（存在）と A4-F（鮮度）は第 2 段（self-hosting）へ後ろ倒しできる**。前倒しは無駄である。

**[BALTHASAR]**: 半分同意し、半分反対する。**A4-R（復旧 + 内容ハッシュ確認）だけは E2E で必要になる**。
E2E は必ず「修正 → 入れ直し → 再試験」のループを回る。そのとき
「**入れ直したつもりで古いキャッシュを測っていた**」が起きると、**偽陽性でも偽陰性でもなく、
測定そのものが無意味になる**。#45542 が「uninstall→install でも更新されない」と報告している以上、
**内容ハッシュ確認なしに E2E の結果を信用してはならない**。

**[CASPAR]**: 結論: **分割する**。

| 検出器 | 位置 | 根拠 |
|:--|:--|:--|
| **A4-R**（復旧 + ハッシュ確認） | **第 1 段（E2E）の前提** | E2E のデバッグループが成立するために必要（BALTHASAR） |
| **A4-P**（存在） | **第 2 段（self-hosting）** | LAM が install して初めて「存在しない」が故障になる |
| **A4-F**（鮮度） | **第 2 段（self-hosting）** | 同上。キャッシュ出所のセッションが存在しないと空振りする |

**この再配置は前セッションの決定の撤回ではなく、ゴール変更に伴う再導出である**。
「検出器は P2 撤去より前」は**第 2 段の内部順序として保持される**。

**採用しなかった選択肢とその理由**:
- **3 種とも前倒し** → LAM が install していない期間に、install 前提の検出器を作ることになる。
  **検査対象が存在しない検査**は「常時緑」になり、機能しているかを確かめられない
- **3 種とも後ろ倒し** → E2E の測定が信用できない（BALTHASAR）

## Atom A4: 並列に走らせられる系統

**[MELCHIOR]**: 5 系統に割れる。S1 が本線で、S2 / S3 / S5 は**本線に触れないので同時に走らせられる**。

**[BALTHASAR]**: 並列化には 2 つの落とし穴がある。

1. **S2（dangling 参照 60 件超）は本線と衝突する**。E2E で `templates/managed/**` を触る可能性があり、
   dangling 参照の修正先も同じ領域である。**同一ファイルへの同時書込**が起きる
2. **委譲可否は「F0 の検証方法が実コマンド 1 行で書けるか」で決まる**
   （`l2-delegation-guardrails.md` §8）。S5（`clause-gate` 参照の構造的問題）は
   **正解が外に無い判断作業**であり、委譲すると漏れが検出されない

**[CASPAR]**: 結論: **本線 1 + 並列 3 とし、S5 は L1 直に残す**。

| 系統 | 内容 | 担当 | 並列可否 | 検証コマンド |
|:--|:--|:--|:--|:--|
| **S1** | E2E 本線（hooks.json → 新規サンドボックス → E1-E6） | **L1 直**（不可逆操作・観測が要る） | 本線 | E1-E6 の各行 |
| **S2** | dangling 参照 60 件超の掃除 | **L3** | **本線の後**（衝突回避） | `verify_reference_resolution.py` |
| **S3** | fresh clone の赤 3 件 | **L2** | **並列可** | 当該テストの pytest |
| **S4** | 孤児キャッシュ（`cache/lam`）+ `lam-global` quarantine | **L1 直** | **並列可** | `claude plugin marketplace list --json` |
| **S5** | `clause-gate` 参照 2 件の構造的問題 / 手順 6（clone-template 廃止） | **L1 直** | 判断のみ・後段 | （判断のため無し） |

**S2 を後ろに置く理由**: 衝突回避（BALTHASAR 1）に加え、**E2E で `templates/` の構成が変わりうる**ため。
先に掃除すると二度手間になる。

**採用しなかった選択肢とその理由**:
- **S2 を並列で回す** → 同一領域への同時書込。E2E のデバッグ中に参照が動くと原因切り分けが壊れる
- **S1 を L2 に委譲** → install / init は**観測しながら判断する**作業で、検証コマンド 1 行に落ちない。
  委譲閾値 1（`model-roster.md` §2）に照らして L1 直

## Atom A5: 自律実行の境界

**[MELCHIOR]**: 第 1 段（E2E）が触るのは `plugins/**`（SE 級）/ `.claude/tests/**`（SE 級）/
`docs/artifacts/**`（SE 級）だけである。**PM 級が 1 つも出ない**。よって承認後は止まらずに走れる。

**[BALTHASAR]**: 3 点で境界を引き直すべきである。

1. **`hooks/hooks.json` の新設は `plugins/` 配下だが、実質は settings 相当の統治物である**。
   等級表の字面では SE 級だが、これを置くと**利用者環境の全ツール呼び出しに介入する**
2. **commit / push はユーザー実行**（`/ship`）。自律実行の範囲外
3. **第 2 段は PM 級だらけ**である。P2 参照切替は `.claude/rules/` を 50 ファイル超触り、
   P5 は `settings.json`（**AI 編集不可**）

**[CASPAR]**: 結論: **第 1 段は自律、ただし hooks.json だけ事前宣言を挟む**。

| 区分 | 扱い |
|:--|:--|
| 第 1 段の SE 級作業（S1 の大半 / S3 / S4） | **自律実行**（承認済み範囲） |
| **`hooks/hooks.json` の新設** | **1 行の事前宣言を挟んでから実行**（等級は SE だが射程が統治的） |
| commit / push | **ユーザー実行**（`/ship`） |
| 第 2 段の PM 級（P2 参照切替 / P5） | **事前宣言 + 承認ゲート**（`permission-levels.md` §PM 級編集の事前宣言義務） |

**採用しなかった選択肢とその理由**:
- **hooks.json も無宣言で置く** → 等級表は満たすが、第 0 原則の「可逆性・復旧コスト」で見ると
  **利用者環境への介入面が一段広がる**変更である。宣言 1 行のコストは中断 1 回未満
- **第 1 段も逐一承認を取る** → ユーザーの明示決定（自律で走り切る）に反する

# HGA #31 の裁定（ゲート条件 1 = AC-W-C-7 到達 + 条件 3 = ユーザー明示指示）

## 裁定の核 —— **網羅表を実行計画に流用したことが誤り**

**なぜ毎回見落とすのか**（HGA の説明）: 項目を n 個並べた瞬間、**n(n−1)/2 本の「独立である」という主張が暗黙に立つ**。

## 合格条件そのものへの疑義（HGA が最優先で述べた）

> **E2E は継ぎ目（transit）だけを検査すべきで、hook のロジックを再検査してはならない。**

ロジックは `.claude/tests/hooks/` の pytest 8 系統で既に担保されている。E2E でロジックを測り直すと、
赤になったとき「**ロジック不良か、輸送不良か**」が分離できず、**E2E の赤が診断情報を持たなくなる**。

この観点で **E6「deny が止める」は検査変数の選択が誤り**。輸送層で問うべきは
「**plugin 経路に置かれた hook が Claude Code から起動され、その出力が採用されたか**」であり、
deny はその一例にすぎない上にフェーズ依存である。証人は「**hook の決定経路だけが書く変数**」でよい。

### L1 による証人の特定（HGA の「要検証 1」を実測で解消）

**`.claude/.session-pm-edit-cache.json` を証人に採用する**。根拠:

- **`post-tool-use.py` だけが書く**（`pre-tool-use.py` は読むのみ / grep 実測 2026-09-05）
- **フェーズ非依存**（PM 級パスへの Edit 成功で記録される / `permission-levels.md` §セッションスコープ降格）
- 第三者プロジェクトには project 層 hooks が無いため、**このファイルが生まれたら plugin 由来と一意に言える**
- user 層 hooks 3 本（HGA が実測）は LAM 計器を書かないため混入しない

これにより **Auto Mode の「発火して自動承認」と「ゲート不在で素通り」の非分離が解ける** ——
証人があれば前者、無ければ後者。

## 第三者性の線引き（HGA の裁定）

> **被検体は「ワークツリー」ではなく「コミット」でなければならない。**

| 段階 | 被検体 | 検出できること | ユーザー操作 |
|:--|:--|:--|:--|
| **自律ループ内** | **HEAD をローカルに clone した複製**を **別名 marketplace** で directory 登録 | **コミット漏れ**（構造的）/ 継ぎ目の透過 | clone のみ（**push 不要**） |
| 前提条件（読取のみ） | `origin/master` と HEAD の差が 0 であることを Git 読取で断定 | **push 漏れを push せずに検出** | なし |
| ループ外・最終 1 発 | github source で install する人手スモーク | Claude Code 側の取得経路のみ | **push**（ユーザー） |

**github source をループに入れない根拠**: それが足すのは「Claude Code 側の取得経路」だけで、
**LAM 固有の故障を 1 つも増やさない**。push をループに巻き込むと自律実行が分断される制約と衝突する。

> **L1 注**: Round 2 の「予行(directory) → 本番(github) の 2 段構え」は**この裁定により棄却**する。
> directory source を**ワークツリー直結ではなく HEAD の clone に差し替える**ことで、
> **push なしにコミット漏れが検出できる** —— 私は「directory か github か」の二択で考えていたが、
> **directory source の被検体を何にするか**という軸を見落としていた。

## 陰性対照（HGA の 3 番目の分岐点）

**シナリオ全体を plugin 無効の状態でもう 1 度走らせ、全証人が赤になることを確認する。**
赤にできない証人は計器ではない。これが 1 巡目 gabriel の D-b 指摘（検査対象 ≠ 脅威）への**構造的回答**であり、
LAM は既に `test_docs_internal_is_pm_and_other_docs_are_not` で同じ実践を持つ。

> **「検査が脅威を捉えているか」は、脅威を注入して赤を見る以外に証明できない。**

# HGA #32 の裁定（ユーザー指示「2 セッション同じ穴に落ちているのが気になる」/ ゲート条件 3）

## 問い

**L1 は 2 セッション連続で同型の分解ミスをした。3 回目をどう防ぐか —— あるいは「防ごうとすること」自体が誤りか。**
提示した対抗仮説: **A**「機構は既に働いている（不要）」/ **B**「検出率が低い（何か足す）」/
**C**「足すと常時鳴る計器になって殺される（置かない）」/ **D**「分解の場面自体を減らす」。

## 裁定の核 —— **A/B/C/D のどれでもない。問題は「分解の出力が持つ語彙」にある**

| | 誤りの形 | L1 が**書かずに主張した関係** |
|:--|:--|:--|
| **#30** | 語の束ね | 「この 2 つは**同じ**」（同一性） |
| **#31** | 独立の誤宣言 | 「この 2 つは**無関係**」（素であること） |

> **どちらも要素間の関係を、L1 の理解から直接「結論」として書いた。
> 同一性も独立性も、本来は各要素が触る状態を書けば導出できる性質であり、宣言する性質ではない。**

**これは LAM が既に 2 回学んだ手と同型である** —— rule-001 の恒久解（散文からの推論をやめて**宣言欄を読む**）/
R3 機構 #7（**維持リストを持たず基質から導出する**）。

### 各仮説の裁き

| | 裁定 | 理由 |
|:--|:--|:--|
| **A** | **棄却** | 「2 回とも拾えた」は事実だが**拾えなかった分は定義上見えない**。「15 対中 2 対」は主張の本数であって誤りの本数ではなく、**再現率は未測定**。A は「失敗の証拠がない」を「成功」と読み替えており、**自己検証の限界そのもの** |
| **B** | 診断は正しいが**処方が違う** | 対の独立性検査は **n² で伸びる**ので検出側を強化しても勝てない。**#31 が効いたのは検出を強めたからではなく、証明不能な主張の本数を n² から n に落としたから**。修正すべきは検出器ではなく**表現** |
| **C** | 懸念は**当たらない** | 提案するのは**条文ではない**（下記）。表の列は鳴らない |
| **D** | 核は正しいが**過剰** | 「刻まない／委譲しない」は不可能（今回は実際に 14 ステップある）。**「切り方を話題から状態へ変える」が D の正しい読み**で、#31 が既に行った |

## 3 回目の穴の予測 —— **「宣言された状態が、実際の状態より小さい」**

同一性（#30）・独立性（#31）の次に同じ根から出る 3 つ目は、**状態の名指しそのものの誤り**。
状態を書く欄ができた瞬間、その欄が L1 の**理解**で埋まる。具体形は 2 つ:

| # | 形 | 具体例 |
|:-:|:--|:--|
| 1 | **hook 副作用の未申告** | LAM で書くのは step ではなく **step + 発火した hook**。PM 級 Edit が `.session-pm-edit-cache.json` を書き、pytest が `test-results.xml` と `tdd-patterns.log` を書き、skill の Step が `current-phase.md` を書く。**L1 は直接書込だけを宣言し hook 経由を落とす**。確定版 Step 11 でキャッシュ書込を拾えたのは**それが証人だったから**であり、証人でない副作用は同じ確度では拾えない |
