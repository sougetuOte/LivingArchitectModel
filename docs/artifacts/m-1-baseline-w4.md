## DoD-4 の判定条件と項目 3 の除外

**項目 3（`tdd-patterns.log` FAIL→PASS 率）を DoD-4 の判定条件から除外する。**

**理由**（W0-M1-T2 §T3 で「案 1」として確定済 / `m-1-baseline-w0.md` L177-200, L604）: 計器（JUnit XML の鮮度判定）は W0 で修正されたが、**修正前に蓄積されたログは盲目の計器で採られている**。W0 側を全履歴で算定すると、W0↔W4 の差分に「条項トリアージの効果」と「計器が変わったこと」の両方が混入し、差分が何を意味するか決まらなくなる。

したがって:

- **W0 側**: 算定しない（盲目の計器で採られた履歴を起点にしない）
- **W4 側**: 実測値として報告する（修正後の計器による観測のため有効）
- **DoD-4 の判定**: 項目 1（pytest regression）と項目 5（PM 級発火数）で行う

### 計器が W4 で作動したことの記録

W3 では `tdd-patterns.log` に本 Wave の Red→Green が記録されなかった（検証コマンドの `-o addopts=""` が `--junitxml` を無効化していたため / `m-1-baseline-w3.md` §項目 3 の注記）。

W4 では **1 ペアが記録された**。W4-M1-T1 の TDD で `-o addopts=""` を付けない素の `pytest` が実行され、JUnit XML が生成されたためである（`tests=8` は `test_update_model_skill.py` の 8 件と一致）。

**これは W3 の欠測が機構の故障ではなく検証コマンドの書き方に起因することの実証**であり、NFR-2（新規機構を追加しない）の下で対処を見送った判断が妥当だったことを裏づける。

## NFR-6 の遵守

**測定結果は報告するが、それ自体を DoD 判定条件として用いない。**

項目 6 は W0 比 **+11,801 字**（154,837 → 166,638）で、**M-1 は規律本体の総量を増やして終わっている**。この事実を隠さず記録するが、**削減量の目標達成率として評価しない**（NFR-6 受け入れ条件 1・3）。

増減の帰属:

| 期間 | 差分 | 帰属 |
|:-----|-----:|:-----|
| W0 → W1 | ±0 | W1 は判定のみの Wave（適用しない / 順序制約 3） |
| W1 → W2 | **+14,193** | 条項トリアージ 42 件の適用が -2,827 字、`model-roster.md` 新設が +17,020 字 |
| W2 → W3 | **-2,392** | `/doctor` の履歴削除（commit `1aa50a9`）に帰属。W3 の作業由来ではない |
| W3 → W4 | **±0** | W4 は規律本体（`CLAUDE.md` / `.claude/rules/`）を 1 文字も編集していない |

**+11,801 字の主因は `model-roster.md`（+17,020 字）の新設**である。SSOT の器を作ると、重複が減っても集約先そのものが常時ロードに乗るため総量は増える。この構造は W2 末の時点で認識され記録されている（`m-1-baseline-w2.md`）。W4 retro の評価軸に持ち込むのは**この構造の記述であって、増減の数値目標ではない**。

> **項目 6 は skills を含まない**（対象は `CLAUDE.md` + `.claude/rules/` のみ）。W3 の progressive disclosure 化（初回ロード -13,471 est. tok）は本項目に原理的に現れない。詳細は `m-1-baseline-w3.md` §項目 6 の注記。
