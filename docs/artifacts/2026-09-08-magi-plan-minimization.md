## Step 1: Divergence

### MELCHIOR（推進 / Value・Speed）

1. **第 1 段 E2E は既に合格している。製品としては「動く」状態に到達済み**である。残りは全て「より綺麗に動く」であって「動く」ではない。停止規則をここに置けば、**残務の大半は今日消える**。
2. **160 sites の散文参照は、1 行の凡例で解決できる**。「本文書中の `docs/` `.claude/` で始まるパスは LAM 上流リポジトリ（URL）を指す」を配布物の入口に置けば、160 個のリンクが**規約によって解決可能**になる。R-P の codemod・逆写像・往復恒等テスト・到達性検査・T2 差替が**丸ごと不要**になる。
3. **11 sites のフェンス内コマンド**だけが本物の欠陥で、これは**手で 1 時間**である。
4. **dashboard の 479 テスト / 10,550 行は、HTML を組み立てる関数への過剰投資**である。しかも視覚検証は恒久 skip（W-20）で、**一番壊れて困る部分だけ検査していない**。
5. **analyzers 565 テストは常用範囲外**。5 日前に「含めない理由が無い」と書いておきながら含めていない。**含めるか捨てるかを今決める**。
6. **記録 6,375 行 / 5 日**は、成果物（コミット差分）より議事録の方が大きい。**議事録が作業になっている**。

### BALTHASAR（批判 / Risk・Debt）

1. **停止規則を「E2E 合格」に置くのは危険**。合格の限界は記録済みで、**E2 / E3 は陰性対照で赤転しない**（＝その 2 イベントは実質未検証）。「合格」を停止規則にすると、**検証されていない部分を検証済みとして畳む**。
2. **凡例 1 行案は、検査可能性を失う**。今の R-P は「配布物に bare な repo 相対パスを残さない」という**構成的に検査できる不変条件**（ADR-0010 追補 4 / PM 級で承認済）である。凡例に置き換えると、**新しい dangling が入っても誰も気づかない**。追補 4 を承認したその翌日に反故にするのは、**条文と実装のドリフトを自分で作る**行為である。
3. **dashboard テストを削るのは、rule-001 の 6 回観測の恒久解を壊す危険がある**。`test_session_state_parser.py` は 479 のうちの一部だが、**どれが load-bearing かを測らずに削れば、次の観測 #7 を招く**。
4. **analyzers を捨てる案は 1 日前に否決されている**。4c-1 で「配る」と PM 級で決めたばかり（`full-review` Stage 1-3 と `ship` の gitleaks が 11 箇所で依存）。**捨てれば配布 skill が再び壊れる**。
5. **Action 7（事後突合）は、前回 gabriel が宣言漏れを実検出したことで発火条件を満たしている**。「異常判定の線」（セッション 32 で引いた）は**繰り上げを命じている**。ここで切ると、**自分で引いた線を自分で無視する**先例になる。
6. **第 2 段 self-hosting を切ると、`.claude/` と `plugins/` の二重実体が恒久化する**。今は生成器と T1/T3 が恒等性を強制しているが、**それは装置が生き続けることを前提**にしている。

## Step 2: Debate

### 争点 1: 停止規則を E2E に置けるか

BALTHASAR の「E2/E3 は陰性対照で赤転しない」は正しい。だが**それは E2E の設計欠陥であって、停止規則を先に延ばす理由ではない**。E2/E3 の証人を直すのは**1 ステップ**であり、「参照 160 箇所の URL 化」より圧倒的に小さい。
→ **合意**: 停止規則は E2E に置く。ただし **E2/E3 の証人を赤転する形に直すことを条件に含める**。

### 争点 2: 凡例 1 行 vs R-P codemod

BALTHASAR の「検査可能性を失う」が本質的。ただし MELCHIOR が指摘するように、**検査可能性は R-P（変換）ではなく census（検出）が担っている**。census は既に動いており、`dev+user-` を 160 sites と正確に数えている。

つまり **2 つは分離できる**:
- **検出**（不変条件が破れたことを知る）= census + ゲート ← **これは残す**
- **変換**（破れを URL に書き換える）= R-P + codemod + 逆写像 + 往復恒等 ← **これが高い**

追補 4 の条文は「(c) 正典 URL のいずれか」を**許容している**が、「機械変換で作れ」とは書いていない。**凡例による規約解決は (c) の一形態として条文に適合しうる** —— ただしこれは条文解釈であり、**PM 級の確認を要する**。

→ **1 巡目の収束点**: 変換を捨て、検出（census のゲート化）＋ 凡例にする。
> **【2 巡目で 2 度否定された】** HGA #36 が「census をゲート化するな」、gabriel が「凡例は追補 4 に適合しない」。両方を採用した確定形は §再 MAGI（2 巡目）を見よ。

### 争点 3: dashboard / analyzers の減量

BALTHASAR の「どれが load-bearing かを測らずに削るな」は正しい。だが**測らずに残し続けることも同じ罪**である。
→ **合意**: 一括削除はしない。**W-20（恒久 skip）と W-19（4〜5 桁マージン）は「緑なのに何も検査していない」と既に判定済み**であり、これらは**測定済みの死骸**である。ここだけを落とす。479 全体の棚卸しは**停止規則の外**（＝終わった後にやるか、やらない）。

analyzers は 4c-1 で「配る」と決めた以上、**常用範囲に入れる**（+3 秒）。**配るものを常用で回さないのは、宣言 > 実際の典型形**である。

### 争点 4: Action 7

MELCHIOR は「計器を増やすな」、BALTHASAR は「自分で引いた線を守れ」。
→ **調停**: 線は「繰り上げ**の判断**を行う」であって「実装する」ではない（残務一覧 §7 の文言 = 「最優先に繰り上げる」／SESSION_STATE = 「繰り上げの判断は次セッションで行う」）。**判断を行い、結論は「作らない」でよい**。理由: **Action 7 が検出したい「宣言漏れ」は、gabriel が現に検出した**。検出器が既にあるものに、二つ目の検出器を作るのは D4（機構の重複）である。

## Step 3: Convergence（CASPAR）

### Atom A1: 「終わり」の定義

**[MELCHIOR]**: E2E 合格をもって終わり。残りは全て改善であって完成ではない。
**[BALTHASAR]**: E2E の証人 2 件が実質未検証。それを畳んで「終わり」と呼ぶのは計器の自己欺瞞。
**[CASPAR]**: 結論 —— **停止規則は「github source からの人手スモーク（X-2）1 発が通ること」に置く。** 理由は 3 つ:
(a) それが**利用者が実際に通る唯一の経路**であり、他の全ての検査はその代理である
(b) **代理を増やしても本物は近づかない** —— 9 セッション・6,375 行の議事録を費やして、本物は一度も測っていない
(c) X-2 は**ユーザー作業でループ外**と分類されてきたが、**それこそが停止しない原因**である。ループ外に置いた瞬間、内側は無限に精緻化できる

**条件**: X-2 の前に **E2/E3 の証人を陰性対照で赤転する形に直す**（1 ステップ / BALTHASAR の指摘を吸収）。

**採用しなかった選択肢とその理由**:
- 「第 2 段 self-hosting の完了をもって終わり」→ self-hosting は**開発側の都合**であり、利用者には見えない。停止規則に据えると、利用者価値ゼロの工程が完成を人質に取る
- 「参照 0 件をもって終わり」→ census は**下界**（素の散文を拾わない）と自ら宣言している。**下界をゼロにしても上界は不明**であり、達成不能な条件を停止規則に据えることになる
- 「Warning 0 件をもって終わり」→ 22 件のうち利用者に届くものは W-14 など数件。大半は開発側の品質であり、停止規則の粒度ではない

### Atom A2: Action 4c-2

**[MELCHIOR]**: 160 sites は凡例 1 行で覆える。codemod・逆写像・往復恒等・到達性検査は全部いらない。
**[BALTHASAR]**: 不変条件の検査可能性を失う。追補 4 を翌日に反故にする。
**[CASPAR]**: 結論 —— **4c-2 を「変換」から「検出 + 凡例」へ縮約する。**

| 4c-2 の構成要素 | 判定 | 理由 |
|:--|:--|:--|
| フェンス内コマンド 11 sites の是正 | **やる**（手作業 1 時間） | **実行すれば落ちる**唯一の集団。機能欠陥 |
| 散文 160 sites の凡例による規約解決 | **やる**（配布物の入口に 1 行 × 数ファイル） | 追補 4 の (c) を「規約で解決する URL」として満たす。**PM 級の条文解釈確認を要する** |
| ~~`census` をゲート化~~ | **撤回**（HGA #36） | **初日から赤 = 常時鳴る計器**。検査可能性は T1〜T5 が担う。census は **reporter** |
| R-P の生成器実装（T1 順 / T3 逆） | **切る** | 変換は検出と分離できる。**双方向の恒等性は永続的な保守債務**であり、160 の死んだ引用に見合わない |
| codemod（182 箇所の機械変換） | **切る** | 同上。前回セッションで codemod が `NameError` を仕込んだ実績があり、**全数 diff レビューのコストが本体より大きい** |
| 往復恒等テスト（両方向） | **切る** | R-P を作らないので対象が消える |
| 到達性検査（URL の path 部が dev に実在） | **切る** | URL を機械生成しないので腐敗面が発生しない。**問題を作ってから解いていた** |
| ~~T2 差し替え（`exists_user` ベース / exit 1）~~ | **撤回**（HGA #36） | **T2 は現状維持**。差し替えれば既存の検出（作者絶対パス / 非配布ディレクトリ参照）を失う |

**採用しなかった選択肢とその理由**:
- 「4c-2 を丸ごとやる（設計どおり）」→ 実測が示す価値は**死んだ引用 160 個のクリック可能化**。1 セッション + 永続保守と釣り合わない
- 「4c-2 を丸ごと切る」→ フェンス内 11 件は**実際に落ちる**ため切れない。また新規 dangling を止める機構が無くなる
- 「凡例でなく `.md` 冒頭に相対 URL base を書く（`[base]: https://...`）」→ Markdown 参照リンク記法は**パス文字列そのものは変えない**ため census が拾い続け、緑にならない。凡例（散文）の方が正直

_r = r'${CLAUDE_PLUGIN_ROOT}'
