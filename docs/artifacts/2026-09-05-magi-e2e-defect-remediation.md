## Atom A1: D-1 の目標形

**[MELCHIOR]**: 目標形は `lam-harness:<name>` で確定している。ADR-0010 I-4 が Accepted で、R-1 追補が
agents への射程まで明記済み。E2E の生エラーはその追補を**独立に再確認した**にすぎない。
再論は通貨の無駄であり、`hga-summoning.md` §争点 E の「一度決めたら条件変化まで再論しない」に該当する。
むしろ「決定が 2 か月実装されなかった」ことのほうが問題で、**実装を急ぐべき**。

**[BALTHASAR]**: 3 点留保する。(i) I-4 の条文は「**スキル参照**は名前空間を常に明示する」であり、
agents への拡張は**追補の観測メモ**として書かれている。条文本体は更新されていない —— 本セッションが
繰り返し見てきた「**実装/観測と条文のドリフト**」と同型で、条文側を直さなければまた失われる。
(ii) **bare `test-runner` が組み込みとして存在する**という新事実は ADR-0010 にない。名前空間化は
衝突回避として**追加の根拠を得た**が、同時に「LAM の `test-runner` は組み込みに隠される可能性」という
**未評価のリスク**を露呈している。(iii) 目標形の確定と、**現在の LAM 本体が壊れないこと**は別問題。

**[CASPAR]**: 結論 —— **目標形は `lam-harness:<name>` で確定。再論しない**（ADR-0010 I-4 + R-1 追補 / 争点 E 規律）。
ただし BALTHASAR (i) を受け、**I-4 の条文本体に agents を含める改訂を伴わせる**（ADR 改訂 = PM 級）。
(ii) の組み込み `test-runner` 衝突は**本 Atom の射程外の新規観測**として A2 の入力に送る。

**採用しなかった選択肢とその理由**:
- **bare のまま維持し plugin 側で名前を変える**（例 agent 名を `lam-gabriel` にして bare 衝突を避ける）→
  I-1「名前空間付き plugin としてのみ配布」の趣旨に反し、名前空間機構を自前の接頭辞で再発明する。
- **両建てを目標形にする** → A3 で評価するが、**目標形**としては I-4「常に明示」に反する。

## Atom A2: 実施時期

**[MELCHIOR]**: 今すぐ 97 箇所を書き換えるべきだ。E2E で正しい形が確定した今が最も安い。

(3) 前倒しは HGA #31 4-a に抵触する。**3 つの逃げ道のうち (a) は規律違反、(b) は A3 で評価、(c) が既定**。

ただし**今やることが 3 つある**（いずれも第 2 段を待たない）:
1. **ADR-0010 I-4 の条文本体に agents を含める改訂**（A1 の CASPAR 結論 / PM 級）

**採用しなかった選択肢とその理由**:

## Atom A3: 回避策（両建て）を採る場合の影響

評価対象の回避策 —— 実行指示を「`lam-harness:<name>` を優先し、解決しなければ bare `<name>`」と両建てで書く。

**[MELCHIOR]**: 両建てなら **LAM 本体も利用者環境も同時に動く**。T3 も保たれる（両側同一文言）。
第 2 段を待たずに D-1 を閉じられ、182 箇所の components 系 37 箇所も動かせる。

**[BALTHASAR]**: 影響を 5 つ挙げる。
1. **I-4 との不整合**: 「常に明示する」の趣旨は**単一の正しい形を持つこと**。両建ては
   「正しい形が 2 つある」と宣言することであり、ADR 改訂なしには置けない。
2. **失敗が観測不能になる**: fallback があると、**namespaced が解決しなかった事実が沈黙する**。
   `rule-001` 観測 #6 と同型（緑のまま誤った状態）。本セッションが 2 度踏んだ型。
3. **97 箇所の大半は散文である**（`gabriel` 63 箇所のうち実行指示は数箇所）。
   両建て文言を 97 箇所に撒くのは**可読性の恒常税**であり、`artifact-length-calibration` の趣旨に反する。
4. **frontmatter は両建てにできない**: `goal-driven-l2-foreman.md` の
   `tools: Agent(goal-driven-l3-executor)` は**単一の文字列しか書けない**。ここだけは分岐が必要になり、
   **両建ては完全解にならない**。
5. **第 2 段で必ず剥がす**。project 側撤去後は bare 側が死ぬため、両建ては**寿命が第 2 段までの一時足場**。
   一時足場を 97 箇所に打つのは、除去コストが導入コストを上回る。

**[MELCHIOR]**: 4 は認める。だが実行指示だけに限れば数箇所で、散文は放置してよいのでは。

**[BALTHASAR]**: それは**両建てではなく「実行指示のみ変換」**という別案である。そしてそれは
A2 の「plugin 側だけ変換」と同じく **T3 が赤**になる —— 両側同一文言なら LAM 本体が壊れるからだ。

**[CASPAR]**: 結論 —— **両建ては採らない**。決定打は **BALTHASAR 4（frontmatter が両建て不能）**と
**2（失敗が沈黙する）**。前者は完全解にならないことの証明、後者は本セッションが 2 度踏んだ失敗形の再生産。

**ただし「回避策を検討した」という記録は残す**（ユーザー指示）。両建てが有効になる条件は
「第 2 段が長期に延びる」場合のみであり、そのときは **frontmatter だけ例外として分岐**し、
**fallback 発火を記録する計器を同時に置く**ことを条件とする。

**採用しなかった選択肢とその理由**:
- **skills から agent 名の直書きを消し役割で書く** → 「利用可能な型から適切なものを選べ」は
  **非決定的**で、MAGI の gabriel 起動のような**特定 agent が必須**の箇所を壊す。
- **project 側 agent の frontmatter `name:` を `lam-harness:gabriel` にする** → 未検証だが、
  `hookify:conversation-analyzer` の実例では**ファイル側 frontmatter は `name: conversation-analyzer`**
  であり（ADR-0010 R-1 の実測）、名前空間は**ファイルではなく配布経路が付ける**。よって不可能と判断。

## Atom A4: D-2（init のガード）の是正形

**[MELCHIOR]**: ガードを削除すればよい。実害は「必ず失敗する行が冒頭にある」ことだけ。

**[BALTHASAR]**: ガードには目的があった —— **plugin root が取れない環境で静かに誤動作しないこと**。
削除すると「取れないまま進む」経路が開く。**同型の教訓が LAM にある**:
`CLAUDE.md` §Python Invocation Convention の段 2 fixup —— **skill 内 bash では `$CLAUDE_PROJECT_DIR` が
unset** のため相対パス形式に書き分ける、という**context 別 form 表**が既にある。
**init の `${CLAUDE_PLUGIN_ROOT}` は、その表に載っていない 3 つ目の context である。**

**[CASPAR]**: 結論 —— **正面（ガード削除）ではなく、context 別 form の追加として扱う**。
具体形は 2 段構え:
1. **skill 本文が展開済みの絶対パスを持つことを利用する**（E2E の実行セッションが実際に採った経路）。
   SKILL.md 内の bash から `${CLAUDE_PLUGIN_ROOT}` を参照しない書き方へ変える
2. **`CLAUDE.md` の Context 別 form 表に「skill 内 bash では `${CLAUDE_PLUGIN_ROOT}` も unset」を追記**
   （**PM 級** / 表は既に「hook では inject される / Bash tool では unset」を扱っており、**同じ表の 1 行**）

**ガードの目的（静かな誤動作の防止）は捨てない** —— 削除ではなく、**判定対象を「変数が取れたか」から
「敷く先のテンプレートが実在するか」へ移す**（基質から導出する / 機構 #7・#11 と同型）。

## 裁定 2: 「宣言 < 実際」の原因は**様式でも対象でもなく、宣言の作られ方**
