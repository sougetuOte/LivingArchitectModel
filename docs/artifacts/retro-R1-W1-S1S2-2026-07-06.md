### Problem (問題だったこと)

- **P1: Fable→Opus gap 事例が 3 件顕在化**
  - **事例 #2 (R1-006)**: Opus (私) の T4 実装漏れ = `verify_reference_resolution.py` の regex `[a-z0-9-]+` が大文字ファイル名 (README.md 等) を捕捉できず → **自作 R-G7 検査ツールに false negative**。Fable spec に「大文字対応」の明示なし = 暗黙知として省略された可能性。
  - **事例 #3 (R1-008)**: Opus の T1 実装漏れ = `r1_inventory.py` の glob が gitignore filter を持たず → ad-hoc script 混入。Fable spec に「tracked file only」明示なし。
  - **事例 #4 (R1-016)**: Sonnet subagent が「`allowed-tools:` は非公式」と誤主張 → context7 で正当と判明。Sonnet の knowledge cutoff + 一次資料参照癖の弱さ。
- **P2: NFR-3 暫定閾値超過 (Critical+Warning = 11)**: 監査 4 モジュール時点で既に暫定閾値 10 超え。全 11 モジュール完了時に更に増える見込み。閾値の妥当性検証を早める必要。
- **P3: inventory JSON の時系列 stale (R1-I13)**: T2 で生成した inventory が T3/T4 のファイル追加を反映しない副作用。R-G8 baseline 再計測時 (W-R5 S2 T2) にズレが発生する構造リスク。
- **P4: rule-001 パターン発火 3 回目 = 閾値 2 のルール承認後も再発**: TDD 内省パイプラインの閾値モデル (trust-model.md) は「1 回で承認 → 恒久解」の想定だった疑い。今回 3 回目でようやく恒久解 → **「承認後の再発でも構造的欠陥を疑うルール」の追加が必要か検討要**。
- **P5: subagent の一次資料参照癖の弱さ (R1-I10 + R1-016)**: 
  - R1-I10: subagent が「verify_reference_resolution.py にテストなし」と誤主張 → 実際は `.claude/tests/rules/` に存在 (T4 output)。subagent が `.claude/tests/scripts/` のみ探索。
  - R1-016: skill-creator のローカル SKILL.md を「一次情報」と誤認 → context7 の Claude Code 公式 docs が真の一次情報。
