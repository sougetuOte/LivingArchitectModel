## §1 Fable の crux 判定サマリ

### crux 1: 案 A を条件付き採用 → 選定基準を差し替えた **案 A'** を推奨

**分岐点**: 要約に載せる命題の選定基準を「RFC 級 (MUST か否か)」ではなく **「その命題の違反が、どの読み込み経路で発生するか」** に差し替える。

- **ambient で縛るべき命題** = 親 SSOT や SKILL.md を開かずに違反が成立する命題 → 要約に書く
- **実行時に縛れば足りる命題** = MAGI を回す文脈では必ず別の文書が開かれている命題 → 要約に不要 (SKILL.md or 参照丸投げ)

### crux 2: 判定軸は「頻度」でも「ダメージ」でもなく **「違反時に別の防御層が拾うか」**

- **M-03 (AoT フレームワーク無改変保存)**: 統合テスト 3 系統 (26+21+16 件 / 06 §6.7) が拾い、git revert で巻き戻る → 要約掲載**不要**、参照 1 行で足りる
- **M-02 (モード宣言) / M-04 (opt-out)**: プロセス違反 / 落ちるテスト**存在しない** → ambient に住まわせる価値

### crux 3: **「半分だけする / retro 境界限定」** (fable-l3-protocol.md × 外部 SSOT)

- 完全監査 (する) = 文面追従 = L4 に接近 → 棄却
- 完全放置 (しない) = currency 問題の鏡像発生 (LAM は外部 SSOT が変わったことに気づけない) → 棄却
- **半分 (snapshot + 変更検知のみ / 修復は etc-to-alembic handoff 経由)** = §8 baseline 成果物が snapshot の自然な置き場
- **頻度は retro 境界のみ** (セッション/監査毎は Outbound Write Ban により検知過剰・修復不能)
