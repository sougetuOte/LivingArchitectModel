## §1 なぜこの Milestone を立ててよいのか

### 主根拠: ユーザーによる明示的な判断（単発 / 日付つき / 非先例化）

M-1 の出口宣言 (a)「**consolidation 系 Milestone のジャンルをここで閉じる**」は、**ユーザー自身が立てた制約**である。したがって「本件が (a) の対象か否か」の判定権はユーザーにある（`CLAUDE.md` Hierarchy of Truth § User Intent が最上位）。

2026-07-27 セッション 17 において、以下を経てユーザーが起票を指示した:

1. L1 が承認要求で「§0 のジャンル判定に明示的に同意いただきたい。ここが崩れると Milestone 自体が成立しない」と提示
2. ユーザーが「承認」と応答

これは **WC-9a「メタ意思の常設化」への防御形式（日付つき・単発・非条項化）に従う**。**「ユーザーが認めれば Milestone を立てられる」を反復可能な規則として残さない。**

### 補強: 経路 2（主権審査）の配布列と主題が一致する

handoff §6「生きている案 #2 = 主権審査」は 2 列で構成され、そのうち**配布列**が本 Milestone の主題そのものである。

| 列 | 問い | 解く問題 |
|:--|:--|:--|
| 残留列（G1） | 「この条項が最後に実際に効いた場面を 1 つ指させるか」 | 常駐面の重さ |
| **配布列（G2）** | **「この条項は私の環境・予算・他プロジェクト・個人名を参照するか」** | **配布物の選別** ← **本 Milestone** |

handoff は同案について「**ユーザーが実施を宣言済み**」と記録し、出力先を「パッケージング境界へ流し、リポジトリは割らない」と定めている。requirements の FR-3 はこれと一致する。

**本 Milestone は配布列のみを扱い、残留列（G1）には触れない**（残留列は常駐面の質量を問う = consolidation 寄り）。

### ジャンルの区別

| | 出口宣言 (a) が閉じたもの | 本 Milestone |
|:--|:--|:--|
| ジャンル | **consolidation 系** —— 規範文書が肥大化していないかを問う棚卸し | **製品定義の変更** —— 何を配布物とするかを決める |
| 問い | 「この条項は要るか」 | 「この条項は**誰のものか**」 |
| 出力 | 条項の削除・移動 | パッケージング境界 |

### WC-11「主権審査の制度化」への回答

> WC-11: 「ユーザーがやれば合法」が反復可能な手続として認知され、(a) が閉じた consolidation ジャンルが**主権の扉から帰還する**（今度はユーザーの注意を燃料にして）

**主権審査を Milestone 化する行為そのものが WC-11 の機序に触れる。** これを認めた上で、以下 3 点で防御する。

1. **D-1 は単発とする。** 「配布境界 Milestone」を反復可能な型（テンプレート・手順・スキル）として残さない
2. **審査の結果は記録し、審査の手続は条文化しない**
3. **扱うのは配布列のみ**。残留列を D-1 に持ち込まない

**D-1 完了後に「次も同じやり方でやろう」と言えてしまう状態になっていたら、防御は失敗している。retro でこれを確認すること。**

## §2 背景

### 2.1 発端となった具体的な詰まり

`.claude/hooks/pre-tool-use.py` の不可逆ガードに、開発者個人の環境の絶対パスが埋まっている。

```python
_OUTBOUND_WRITE_BAN_ROOTS = (Path("D:/work7/Fable-Alembic"),)
_OUTBOUND_WRITE_ALLOW_ROOTS = (Path("D:/work7/etc-to-alembic/handoff"),)
```

MAGI（AoT 3 Atom + gabriel）はこれを「パスの修正」として直すことを**否決**した。兄弟導出 / 設定ファイル化 / 条文パースはいずれも死因つきで記録済み（`2026-07-27-magi-outbound-ban-path.md`）。沈黙の検出は所有者ゲートつきテストで解決済み（commit `6689bd0`）。**残ったのは、この定数が参照する `.claude/rules/fable-l3-protocol.md` が R1 = 配布物に含まれている**という事実である。

### 2.2 未決であることが塞いでいるもの

| 塞がっているもの | 理由 |
|:---|:---|
| ban root の**無条件**実在検査 | 配布先の pytest が落ちるため置けない（現在は所有者ゲートで回避） |
| `hga-summoning.md` の扱い | 個人の予算枠・モデル選択・外部リポジトリを参照する（R1 最大 20,003 バイト / 9 指令） |
| `fable-l3-protocol.md` の扱い | 外部リポジトリ `D:\work7\Fable-Alembic` との連携規律（18,588 バイト / 19 指令 = 指令密度 1 位） |
| 決定 2「配布可能性を維持する」の実効性 | 何が配布物かが未定義のまま「維持する」と宣言している状態 |

### 2.3 現在の配布チャネル（2026-07-27 実測）

**`init-harness` の実体**（`SKILL.md` + `references/templates.md` 実測）:

- 空のディレクトリ 6 件と**雛形ファイル 6 件**（`CLAUDE.md` / `CHEATSHEET.md` / `CHANGELOG.md` / `SESSION_STATE.md` / `.claude/current-phase.json` / `.claude/harness.json`）を**インライン文字列から生成**する足場組みスキル
- **`.claude/rules/` への言及はスキル本体にもテンプレートにも存在しない**（grep 実測 0 件）
- したがって LAM の資産を選別して配る機能を**持たない**

**実際の配布チャネルは README「使い方」の 3 経路であり、いずれもリポジトリを丸ごと渡す**:

| Option | 方法 |
|:--|:--|
| **A（README 推奨）** | GitHub の "Use this template" |
| **B** | `git clone` → `rm -rf .git && git init` |
| **C** | ZIP 展開 → Claude に「配置してください」と指示 |

Option B の直後に「LAM は `.claude/`、`docs/internal/`、`CLAUDE.md` が連携して動作するため、**一式をそのまま使うことを推奨します**」とあり、Option C も「LAM の全ファイルを確認し必要な部分を適応させてください」と全量提示を前提にしている。

**帰結**: **現在の配布物 = リポジトリの全内容**である。`fable-l3-protocol.md` / `hga-summoning.md` / `D:/work7/Fable-Alembic` のハードコードは、**31 回のリリースすべてで配布されてきた**。

### 2.4 self-hosting との関係（制約）

HGA #22 が「**self-hosting は原則ではなく LAM 唯一の QA 機構**」と裁定した。したがって:

- **開発環境と配布物をリポジトリ境界で分けてはならない**（移住 = 死んだ案 #5 / ユーザー撤回済）
- 境界は**パッケージング境界**として実装する
- 2026-07-27 の WSL2 検討で ① 現状維持が確定した理由も同根（**WC-12「dogfooding の名目化」のプラットフォーム版**）

## §5 訂正記録（同じ誤りを再導入しないために）

### 訂正 1（v1.0 → v1.1）: `init-harness` の選別機構は実在しなかった

初版の FR-2 は「`init-harness` の**既存選別機構**を実装先とする」と定めていたが、**そのような機構は存在しない**（§2.3）。L1 が背景タスクに書いた未検証の記述を requirements に持ち込んだもので、**ユーザー承認後に実物を読んで判明**した。

**原因**: `upstream-first.md` §設計フェーズへの適用（「設計書に具体を書く前に裏取りする」）の不履行。

### 訂正 2（v1.1 → v1.2）: §0 の合法性論法が撤回済みブロックに依拠していた

初版 §0 は `CHANGELOG.md` の「次 Milestone の性格の明示」を主根拠に置いていたが、**その一節は撤回された移住ブロックに属し、「存続する決定」の列挙（決定 2 / 決定 4 / 取引 #1 の erratum / 主権的解除の非先例化記録）に含まれていない**。

L1 の「移住は撤回されたがジャンル判定は撤回されていない」という読みは**解釈**であって、CHANGELOG 側にも MAGI / gabriel / HGA のいずれの裁定にも明示の裏づけがなかった。**この読みを根拠として復活させないこと。**

**検出**: 独立コンテキストの `spec-critic` レビュー（判定 `go-with-fixes`）。**同一文書で L1 の自己確認が 2 度失敗した**ことになる。

### spec-critic レビューの反映一覧（v1.2）

| severity | 指摘 | 対応 |

| warning | FR-2 と FR-3 が「マニフェスト」を一方で禁止例・他方で必須成果物として扱う字義矛盾 | FR-2 の禁止対象を「マニフェストを**支える**検査群・分類学・メタデータ列」に限定 |
