# 成果物の長さキャリブレーション

> **条件ロード（R2 / 2026-08-17 誕生ゲート 段 2 で配置 / 台帳 §決定）**: `docs/` 配下の成果物を書く・直すときにのみロードされる。

## 規範（Opus 5 公式ガイド #3 / 保全形）

ディスクに書く成果物は、**実質をカバーしつつ、filler・冗長な要約・boilerplate で膨らませない**。

これは Opus 5 の**既定挙動に対する明示的な打ち消し**である。公式ガイド「Prompting Claude Opus 5」は、指示がなければ Opus 5 が長い成果物を書くと明記しており、**長さは effort では制御されない**（effort は「どれだけ考えるか」であって「どれだけ書くか」ではない）。

## 判断に使う 1 問

**数値は目標でも上限でもない。** 常設の数値ゲージは置かない（誕生ゲートで (i) K/G/M のゲージ化が R5 になったのと同じ理由 —— 数字が先に生まれると通貨化圧を生む）。使うのは次の 1 問のみ:

> **この節を消したら、受け手は判断を誤るか。** 誤らないなら消す。

## 削らないもの（削減は正義ではない）

**根拠・反証・棄却理由・射程の限界**は成果物の実質であって filler ではない。特に「なぜ採らなかったか」は、後続セッションが同じ検討を再走しないための唯一の防波堤である。

削るのは **繰り返し・前置き・自明な要約・定型の再掲・既出文書の引き写し**（参照で足りる）。

## 失効と再武装（R2 要件 (iv) / 設計 §1.2）

本規範は **compaction で失効する**。再武装は **`docs/` 配下の成果物に触れた時点で自動的に起きる**（成果物はそこにしか置けないため、`planning-quality-guideline.md` と同じ自己再武装型）。

失効中に compaction が起きた事実は **R3 機構 #7** が `.claude/compaction-exposure.log` に記録する（台帳 §C #7）。
