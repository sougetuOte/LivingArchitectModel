# モデルロスター（モデル名束縛の単一 SSOT）

> **starter テンプレート**: 初回だけ敷かれます。以後はあなたの資産であり、
> plugin の更新では上書きされません。**値はあなたの環境に合わせて書き換えてください。**
>
> なぜ managed（更新が届く層）ではないか: 層 → モデルの**構造**は汎用ですが、
> どのモデルを使うか・単価・予算は利用者ごとに異なるためです。
> 構造だけを配って値を配らない分離は将来の課題として残っています。

## §0 本ファイルが持つもの / 持たないもの

| | 内容 | 所在 |
|:--|:-----|:-----|
| **持つ** | モデル名の束縛（層 → モデル ID）/ 層内閾値 / 単価 | 本ファイル |
| 持たない | **層の定義**（L1 = 判断 / L2 = 実行 / L3 = 採点） | `CLAUDE.md` |

**モデルが変わったときに更新するのは本ファイル 1 枚**。他のファイルはモデル名を持ちません。
これが単一 SSOT 化の目的です。

hooks は LLM を呼ばない（純粋なスクリプト）。subagents の `model:` frontmatter に
最上位モデルを既定で割り当てないこと —— コストが読めなくなります。

## §2 層内閾値（**要記入 / 下記は出発点**）

| # | 閾値 | 値 |
|:-:|:-----|:---|
| 1 | **委譲可否の第一基準** | 完了条件の「検証方法」が**実コマンド 1 行**で書けるか。書けなければ委譲しない |
| 2 | **直接作業の自己チェック** | Edit 5 回 + Write 1 回を超えるなら委譲を検討する |
| 3 | **司令塔の投入** | 並列子 2 名超かつ複数ファイル横断のとき |
| 4 | **並列度の既定** | 独立タスクは 3-4 並列 |

**閾値 1 と 2 の関係**: 2 は「量」、1 は「性質」。量が閾値を超えても検証コマンドが
書けないなら委譲しません（1 が優先）。
